## LLMについて

# LLMとは

### Large Language Model (LLM)

**膨大なテキストデータと計算資源を用いて構築された巨大な言語モデル**

### どれくらい「大きい」か

- **パラメータ数**: GPT-3で175B（1,750億個）のパラメータ
  - GPT-4は推定1兆以上のパラメータ
- **開発コスト**: GPT-3クラスで数億円と呼ばれる計算費
  - 最新モデルはさらに桁違いの投資

### なぜこんなに大きくする必要があるのか

- データとパラメータを増やすと性能が向上する「スケーリング則」
- 複雑な言語理解・生成には膨大な知識が必要
- 後ほど詳しく解説します

---

# Language Model (言語モデル) とは

### 本質：文脈を受けて「次に来る単語（トークン）」を予測する確率器

$$P(y_t | y_0, y_1, ..., y_{t-1})$$

- $y_t$: 次に来る単語
- $y_0, ..., y_{t-1}$: これまでの単語列

### 例：簡単な文章の続きを予測

**入力**: 「今日の天気は」

**予測確率**:
- 「晴れ」: 0.4
- 「曇り」: 0.3
- 「雨」: 0.2
- 「猫」: 0.001

→ 文脈に合った単語ほど高い確率を持つ

---

# 言語モデルの変遷

### 統計的な古典モデル

- **N-gram**: 直前のN個の単語から次を予測
  - シンプルだが、長い文脈を考慮できない

### ニューラルネットワークを用いた現代モデル

- **RNN/LSTM** (2010年代): 系列を順番に処理
  - 長距離依存が難しい、並列化できない
- **Transformer** (2017年〜): Attentionのみで構成
  - 並列化可能、長距離依存に強い
  - **現在のLLMの基盤技術**

## 自然言語の特徴量

---

# 特徴量について

### コンピュータビジョン (CV) の場合

- **RGB値**: 数値そのものが意味を持つ
  - R=255, G=0, B=0 → 赤色
  - 数値の大小が色の近さと連動

### 自然言語の難しさ

- **Unicodeなどの文字コード**: 数値の大小が意味の近さと連動していない
  - 「犬」(U+72AC) と 「猫」(U+732B) のコード値は近いが、意味的な類似性とは無関係
  - 文字コードをそのまま特徴量として使うのは不適切

**→ 単語を「意味を持つベクトル」に変換する必要がある**

---

# 分布仮説

### Distributional Hypothesis

**「単語の意味は、その周辺に現れる単語によって決まる」**

- 言語学の仮説（1950年代〜）
- 分散表現が成立するための理論的支柱

### 例

- 「犬」の周辺に現れる単語: 「散歩」「飼う」「吠える」「ペット」
- 「猫」の周辺に現れる単語: 「飼う」「なでる」「鳴く」「ペット」
- → 「犬」と「猫」は似た文脈で使われる = 似た意味を持つ

**→ 周辺単語の統計から、単語の意味をベクトルで表現できる**

---

# 分散表現・埋め込み表現

### 特徴量としての分散表現

**単語を高次元の密ベクトル（実数の列）で表現する**

### 埋め込み空間 (Embedding Space)

- 意味が近い言葉は、空間上の距離（類似度）が近くなる

**例**:
- 「犬」: [0.8, 0.1, 0.3, -0.5, ...]
- 「猫」: [0.7, 0.2, 0.4, -0.4, ...] ← 犬に近い
- 「車」: [0.1, 0.9, -0.2, 0.8, ...] ← 犬から遠い

### メリット

- 意味の類似性を計算可能（ベクトルの内積やコサイン類似度）
- 機械学習モデルの入力として使用できる

# 代表的な手法

### Word2Vec (2013年)

- 周辺単語から対象単語を予測する学習
- 「王 - 男 + 女 = 女王」のような意味演算が可能

### GloVe (2014年)

- 単語の共起統計を行列分解

### Transformer による埋め込み (2017年〜)

- **現在の主流**: TransformerのEmbedding層
- 文脈に応じて動的に変化する埋め込み（Contextual Embedding）
- 「銀行」という単語も「お金」の文脈と「川」の文脈で異なるベクトル

# 言語モデルの評価

### Perplexity (PPL)

**モデルが次の単語をどれだけ「迷わずに」予測できているか**

$$\text{PPL} = \exp\left(-\frac{1}{N}\sum_{i=1}^{N}\log P(y_i|y_0, ..., y_{i-1})\right)$$

- **低いほど良い**: モデルが正しい単語に高い確率を与えている
- **高いと悪い**: モデルが迷っている、確率分布が平坦

### 直感的な理解

- PPL = 2 → 次の単語の候補が平均2個
- PPL = 100 → 次の単語の候補が平均100個（迷いまくり）

---

# 温度 (Temperature)

### 確率分布の「尖り方」を調整するパラメータ

$$P'(y_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

- $T$: 温度パラメータ
- $z_i$: モデルの出力（logit）

### 温度の効果

- **低温 (T < 1)**: 確率分布が尖る → 決定的で堅実な出力
  - T=0.1: 「今日の天気は晴れです。」
- **高温 (T > 1)**: 確率分布が平坦 → 多様で創造的な出力
  - T=2.0: 「今日の天気は、まるで夢のように素晴らしい晴天です！」

**実務**: クライアント側で最も重要な調整パラメータ

---

# 発展: decoding戦略

### 次の単語をどう選ぶか

#### Greedy Decoding

- 常に確率最大の単語を選択
- 決定論的だが、創造性がない

#### Beam Search

- 複数の有望なパス（候補）を同時に保持して探索
- 翻訳などで使用されるが、計算コスト高

#### Top-k Sampling

- 確率上位k個からランダムにサンプリング
- k=50 → 上位50個の候補から選ぶ

#### Top-p (Nucleus) Sampling

- 累積確率がpに達するまでの候補からサンプリング
- p=0.9 → 累積確率90%の候補から選ぶ

## Attention機構

---

# RNNによる系列処理

### 翻訳を例にした逐次処理

**入力（英語）**: "I love cats"  
**出力（日本語）**: "私は猫が好きです"

### RNNの処理

1. "I" を処理 → 隠れ状態 $h_1$
2. "love" を処理 → 隠れ状態 $h_2$ (前の $h_1$ を考慮)
3. "cats" を処理 → 隠れ状態 $h_3$ (前の $h_2$ を考慮)
4. $h_3$ から「私は猫が好きです」を生成

### 自己回帰 (Auto-regressive) 性

- 過去の出力を次の入力として使う
- 1単語ずつ順番に生成

---

# RNNの課題

### 1. 長距離依存性の問題

- 文頭の情報が文末まで伝わりにくい
- 長い文章になると「忘れる」

**例**: "The cat, which we adopted from the shelter last year, **is** very cute."
- 主語 "cat" から離れた位置の動詞 "is" の単数形を正しく選ぶのが難しい

### 2. 動的に特定の情報へ注目するのが難しい

- 翻訳時に「どの単語に注目すべきか」を動的に変えられない

### 3. 並列化できない

- 1単語ずつ順番に処理する必要がある
- GPUの並列計算能力を活かせない

**→ Attentionで解決！**

---

# seq2seq with attention

### Cross Attention: 翻訳時にEncoderの特定の表現に「重み付け」して注目

**入力（英語）**: "I love cats"  
**出力（日本語）**: "私は猫が好きです"

1. Encoderが全単語を処理 → $h_1, h_2, h_3$
2. Decoderが「猫」を生成する時、$h_1, h_2, h_3$ のどれに注目すべきか？
3. **Attention**: "cats" の $h_3$ に高い重みを付けて注目
4. 重み付き平均を計算して「猫」を生成

### メリット

- 長距離依存を解消
- 翻訳時にどの単語に注目しているか可視化可能

### 課題

- 依然としてRNNベースなので、並列化できない

---

# attentionについて詳しく

### Scoreの計算方法

1. **内積 (Dot-product)**: $\text{score}(h_i, s) = h_i^T s$
2. **加法 (Additive)**: $\text{score}(h_i, s) = v^T \tanh(W_1 h_i + W_2 s)$

### Attention Weight の計算

$$\alpha_i = \frac{\exp(\text{score}(h_i, s))}{\sum_j \exp(\text{score}(h_j, s))}$$

- Softmaxで確率分布に変換

### Context Vector の計算

$$c = \sum_i \alpha_i h_i$$

- 注目度に応じた重み付き平均

---

# seq2seq with attentionの課題

### RNNの構造上の限界

- **一歩ずつしか進めない**: 前の時刻の計算が終わらないと次に進めない
- **学習の並列化ができない**: GPUを活かせない
- **学習時間が長い**: 大規模データでの学習が困難

### Attentionは素晴らしいが、RNNがボトルネック

**→ RNNを捨てて、Attentionのみで構成したら？**

**→ Transformerの誕生！**

## Transformer

---

# Transformerの誕生

### "Attention Is All You Need" (2017)

**RNNを捨て、Attentionのみで構成した革命的アーキテクチャ**

### メリット

1. **大規模な並列化が可能**: 全トークンを同時に処理
2. **長距離依存に強い**: 全トークン間の関係を直接計算
3. **学習が高速**: GPUを最大限活用

### 位置符号化 (Positional Encoding)

- RNNと違い、順序情報がない
- 位置をベクトルで付与: $\text{PE}_{pos, 2i} = \sin(pos / 10000^{2i/d})$

### QKVモデル

- **Query (Q)**: 「何を探すか」
- **Key (K)**: 「どこにあるか」
- **Value (V)**: 「実際の値」

---

# Attentionの計算式

### Scaled Dot-Product Attention

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

- $Q$: Query行列
- $K$: Key行列
- $V$: Value行列
- $d_k$: Keyの次元数（スケーリング係数）

### 直感的説明

1. **QとKの類似度を計算**: $QK^T$ → どのKeyに注目すべきか
2. **Softmaxで確率分布に変換**: 重要度を0〜1の範囲に正規化
3. **Valueを重み付け合計**: 重要な情報を取り出す

---

# Self-Attention

### 入力系列内の単語同士の関係を学習

**例**: 「彼は本を読んだ」

- 「彼」は誰？ → 文脈から「本を読んだ」主体
- 「読んだ」の主語は？ → 「彼」

### Self-Attentionの処理

1. 各単語をQuery、Key、Valueに変換
2. 各単語が他の全単語との類似度を計算
3. 重要な単語に注目して新しい表現を生成

**→ 文脈を考慮した動的な表現が得られる**

---

# Multi-Head Attention

### 複数のAttentionを並列実行

- 異なる視点（head）で同時に情報を抽出
- 例：8 heads → 8種類の注目パターンを学習

### 構造

```
Input → [Head1, Head2, ..., Head8] → Concat → Linear → Output
```

### メリット

- 多様な関係性を捉えられる
  - Head1: 主語と述語の関係
  - Head2: 修飾語と被修飾語の関係
  - Head3: 文脈的な依存関係
- 性能向上

---

# Transformerの詳細

### Transformer Block の構成

1. **Multi-Head Self-Attention**: 入力同士の関係を学習
2. **Residual Connection (残差接続)**: $\text{output} = \text{input} + \text{attention(input)}$
3. **Layer Normalization**: 学習を安定化
4. **Feed Forward Network**: 各トークンを独立に変換
5. **再びResidual Connection と Layer Normalization**

### Decoderでの Masking

- **未来の情報を見ないようにする工夫**
- 生成時に「次の単語」を予測するため、未来の単語は隠す

---

# Attentionの動的な性質

### 入力に応じて注目先が変わる

**例1**: "The animal didn't cross the street because **it** was too tired."
- "it" は "animal" に注目

**例2**: "The animal didn't cross the street because **it** was too wide."
- "it" は "street" に注目

### 従来の固定的な処理との違い

- **RNN**: 固定的な処理フロー
- **Attention**: 入力に応じて動的に注目先を変える

**→ より柔軟で高精度な理解が可能**

---

# 自己回帰の仕組み

### 概念的にはRNN時代と同じ

1. 開始トークン `<start>` から生成開始
2. 1トークン目を予測
3. 予測した1トークン目を入力に追加
4. 2トークン目を予測
5. 繰り返し...

### Transformerでの違い

- RNN: 1ステップずつ順番に処理
- Transformer: 過去の全トークンを並列に処理

**→ 生成は逐次的だが、学習は並列化可能！**

---

# 発展: Transformerの計算量と最適化

### 計算量の問題

**Attentionの計算量**: トークン長 $n$ に対して $O(n^2)$

- 長い文章（数千トークン）になると計算量が爆発
- メモリも $O(n^2)$ 必要

### Sparse Transformer

- 注目先を間引いて $O(n\sqrt{n})$ に削減
- 全トークンではなく、近傍や特定パターンのみに注目

### Flash Attention

- **GPUメモリへのアクセスを最適化**
- アルゴリズムは同じだが、劇的に高速化（2〜4倍）
- 長いコンテキストでの学習を可能に

---

# 発展: 推論向きGPUの性質

### 演算速度より「帯域（メモリバス幅）」が重要

- LLMの推論は **メモリバウンド**
- パラメータをメモリから読み出す速度がボトルネック

### 具体例

- **H100 GPU**: メモリ帯域 3TB/s
- **A100 GPU**: メモリ帯域 2TB/s
- → H100の方が推論が速い（演算性能だけでない）

### 量子化の重要性

- FP16 → INT8 に変換すると、メモリ転送量が半分
- 推論速度が2倍に（精度はほぼ維持）

---

# 発展: KVキャッシュ

### 過去の計算結果を再利用して高速化

**問題**: 毎回全トークンのAttentionを計算するのは無駄

**解決**: Key と Value を保存（キャッシュ）して再利用

### 仕組み

1. 1トークン目生成: K, V を計算してキャッシュ
2. 2トークン目生成: 過去のK, Vを再利用、新しいトークンのK, Vだけ計算
3. 3トークン目以降も同様

### 効果

- **2文字目以降が爆速に**

# 発展: 学習と法則

### 事前学習 (Pre-training)

**大規模な「穴埋め問題」による自習**

- 次単語予測（GPT）やMasked LM（BERT）
- ラベルなしデータで学習可能
- 数兆トークン規模のデータ（Web、書籍、論文、コードなど）

### スケーリング則 (Scaling Laws)

**計算量・データ・パラメータを増やすとロスがべき乗で下がる**

$$L(C) \propto C^{-\alpha}$$

- $L$: Loss（低いほど良い）
- $C$: 計算量
- $\alpha$: べき指数（約0.05〜0.1）

**→ 大きくすればするほど賢くなる（ただし効率とトレードオフ）**

# 具体的な画像生成モデル

### GAN (Generative Adversarial Network)

- Generator（生成器）とDiscriminator（識別器）の対立学習
- かつては主流だったが、学習が不安定

### 拡散モデル (Diffusion Model)

- **現在の主流**
- 画像にノイズを加える過程と、ノイズを除去する過程を学習
- 高品質で安定した生成

### 拡散モデルは「枠組み」

- 具体的なデノイズ器（U-NetやViT）を内包
- **DiT (Diffusion Transformer)**: ViTを採用した最新形式

---

# 拡散モデルの学習

### DDPM (Denoising Diffusion Probabilistic Models) 論文がベース

**学習の流れ**:

1. 訓練画像にノイズを段階的に加える（拡散過程）
2. 各段階で「どんなノイズが加わったか」を予測するモデルを学習
3. 学習したモデルで、ノイズから画像を復元（逆拡散過程）

**損失関数**:

$$L = \mathbb{E}_{t, x_0, \epsilon}\left[\|\epsilon - \epsilon_\theta(x_t, t)\|^2\right]$$

- $\epsilon$: 実際に加えたノイズ
- $\epsilon_\theta(x_t, t)$: モデルが予測したノイズ

---

# 拡散過程 (Forward Process)

### 画像に段階的にノイズを加え、標準正規分布へ

$$q(x_t | x_{t-1}) = \mathcal{N}(x_t; \sqrt{1-\beta_t} x_{t-1}, \beta_t I)$$

- $x_0$: 元画像
- $x_t$: ステップ $t$ でのノイズ付き画像
- $\beta_t$: ノイズスケジュール（徐々に大きくする）

**最終的に**: $x_T \sim \mathcal{N}(0, I)$ （完全なノイズ）

### イメージ

1. 元画像 → 少しぼやける
2. → さらにぼやける
3. → ...
4. → 完全なノイズ

---

# 逆拡散過程 (Reverse Process)

### プロンプトを条件に、ノイズから画像を復元

$$p_\theta(x_{t-1} | x_t, c) = \mathcal{N}(x_{t-1}; \mu_\theta(x_t, t, c), \Sigma_\theta(x_t, t, c))$$

- $c$: 条件（テキストプロンプトなど）
- $\mu_\theta$: モデルが予測する平均
- $\Sigma_\theta$: モデルが予測する分散

### 生成の流れ

1. ランダムノイズ $x_T$ から開始
2. プロンプト "a cat" を条件に、$x_{T-1}$ を生成
3. → $x_{T-2}$ を生成
4. → ...
5. → $x_0$ （完成した画像）

**→ ここでもAttentionが機能（テキストと画像の対応）**

---

# 拡散モデルまとめ

### フロー

1. **学習時**: 画像 → ノイズ追加 → ノイズ予測を学習
2. **生成時**: ノイズ → 逆拡散 → 画像

### メリット

- 高品質な生成
- 学習が安定
- 条件付け（プロンプト）が容易

### デメリット

- 生成に時間がかかる（数十〜数百ステップ）
- 計算コストが高い

---

# 発展: LDM (Latent Diffusion Model)

### 潜在空間での効率的な処理

**問題**: 高解像度画像（512×512など）での拡散は計算コスト大

**解決**: 画像を低次元の潜在表現に圧縮してから拡散

**仕組み**:

1. **VAE Encoder**: 画像 → 潜在表現（64×64など）
2. **拡散過程**: 潜在空間で実行
3. **VAE Decoder**: 潜在表現 → 画像

### 代表例

- **Stable Diffusion**: LDMの最も有名な実装

**→ 高速かつ高品質な生成が可能**

---

# 発展: LoRA (Low-Rank Adaptation)

### 小さな追加重みで特定のスタイルを学習

**問題**: 特定のスタイル（アニメ風、特定の人物など）を学習するには全体を再学習？

**解決**: 小さな追加重み（低ランク行列）だけを学習

**数式**:

$$W' = W + \Delta W = W + BA$$

- $W$: 元の重み（固定）
- $B, A$: 低ランク行列（学習）

### メリット

- 学習データ・時間・メモリが少なくて済む
- 複数のLoRAを切り替えてスタイル変更可能

# CLIP (Contrastive Language-Image Pre-training)

**構造**:

- **Image Encoder**: Vision Transformer (ViT)
- **Text Encoder**: Transformer
- **共通埋め込み空間**: 両方を同じ次元に射影

### 応用

- Zero-shot画像分類: 学習していないカテゴリも分類可能
- Stable Diffusionのテキスト条件付け

# 構造化出力

### JSON Schemaなどによる出力形式の強制

**問題**: LLMの出力は自由形式で、パースが難しい

**解決**: スキーマを指定して、必ず従わせる

**例**:

```python
schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "age": {"type": "integer"},
        "email": {"type": "string"}
    },
    "required": ["name", "age"]
}

response = client.chat.completions.create(
    model="gpt-4",
    messages=[...],
    response_format={"type": "json_schema", "schema": schema}
)
```

**→ 確率的な挙動を制御し、パース可能な出力を保証**

# LLMの性質と制御

### 確率モデルゆえの振る舞い

- 同じ入力でも出力が変わる
- 時に誤った情報を生成（ハルシネーション）
- 複雑なタスクを一度に解くのは難しい

### いかにワークフローで制御し能力を引き出すか

- **単発のプロンプト** → **複数ステップの処理**
- **固定的なフロー** → **動的な判断**

**→ Agent の設計が重要**

---

# workflow と agentic loop

### Workflow: 定型的な連鎖

```
入力 → 処理1 → 処理2 → 処理3 → 出力
```

- 事前に決められたステップを順番に実行
- 確実だが、柔軟性に欠ける

### Agentic Loop: 推論による自律的な反復と改善

```
入力 → 計画 → 実行 → 評価 → (必要なら再計画) → 出力
```

- LLMが状況を判断して次のアクションを決定
- 柔軟だが、制御が難しい

**→ 両方を組み合わせて最適化**

---

# エージェントの設計

### Core: LLMの推論能力

- **Planning**: タスクを分解して計画を立てる
- **Feedback**: 実行結果を評価して修正

### 主要コンポーネント

1. **Planning Node**: タスク理解・計画立案
2. **Action Node**: ツールの実行
3. **Observation Node**: 結果の取得
4. **Reflection Node**: 結果の評価・修正判断

---

# ReAct (Reasoning + Acting)

### Thought → Action → Observation の繰り返し

**フロー**:

1. **Thought**: 「次に何をすべきか考える」
2. **Action**: ツールを実行
3. **Observation**: 結果を観察
4. **1に戻る（ゴール達成まで繰り返し）**

### メリット

- 透明性が高い（思考過程が見える）
- 動的にツールを選択できる
- 複雑なタスクを段階的に解決

evaluation_prompt = f"""

評価基準:

1-5のスコアで評価してください。

# Plan and solve

**仕組み**:
